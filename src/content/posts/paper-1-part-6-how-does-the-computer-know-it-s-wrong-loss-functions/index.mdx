From Part 5: a linear classifier computes scores for each label and picks the highest one.

Now, if the highest score is the wrong label, how wrong is it? And how do you tell the computer to improve?

The answer is **loss functions**.

## Wrongness as a Number

A naive approach: a prediction is either right or wrong. Binary. You get 1 point or 0 points. This seems logical, and it's fine for reporting a final accuracy score, but it's too coarse to guide learning: it can only tell the computer whether it was right or wrong, not how to improve.

Imagine two scenarios:

**Scenario A:** The correct label is "cat" and the scores are:
- cat: 10
- dog: 9
- bird: 8

The classifier picks "cat" (correct), but it was close. Dog was nearly as high. This feels uncertain.

**Scenario B:** The correct label is "cat" and the scores are:
- cat: 100
- dog: 1
- bird: 0.5

The classifier picks "cat" (correct), and dog was far behind. This feels confident.

Both get full credit if you only count right/wrong, but Scenario B is objectively better. The classifier was more sure.

A loss function measures not just whether the guess was right, but *how right*. If you got it wrong, how badly? If you got it right, how confident were you?

## Hinge Loss

Here's one approach called **hinge loss**. It's the loss function used by Support Vector Machines (SVMs), a traditional type of classifier that predates deep learning.

If the correct label has score `S_correct` and the highest wrong label has score `S_wrong`, the loss is:

```
loss = max(0, 1 + S_wrong - S_correct)
```

Let's walk through this:

**If you're confident and correct:**

```
S_correct = 10    # the correct label's score
S_wrong = -5      # the highest-scoring wrong label

loss = max(0, 1 + (-5) - 10)
     = max(0, -14) = 0
```

You pay no penalty.

**If you're correct but not by enough:**

```
S_correct = 10
S_wrong = 9.5

loss = max(0, 1 + 9.5 - 10)
     = max(0, 0.5) = 0.5
```

You pay a small penalty of 0.5. You were correct, but the correct score beat the wrong score by only 0.5, less than the margin of 1 that hinge loss demands, so it still nudges you to separate them further.

**If you got it wrong:**

```
S_correct = 5
S_wrong = 10

loss = max(0, 1 + 10 - 5)
     = max(0, 6) = 6
```

You pay a penalty of 6. The more confidently wrong you were, the higher the penalty.

The formula is saying: "I want the correct label's score to be higher than the wrong label's score, by at least a margin of 1. If it's not, penalize me."

The name "hinge loss" comes from the shape of that rule when you graph it. Put the margin (how much the correct score beats the wrong score) on the horizontal axis and the loss on the vertical axis. Once the margin reaches 1, the loss is flat at zero. Below a margin of 1, the loss rises as a straight sloped line: the smaller the margin, the bigger the penalty. Those two pieces meet at a corner, and a flat part joined to a sloped part at a bend looks like a door hinge.

![Graph of hinge loss: a sloped line falling to zero at a margin of 1, then flat at zero for larger margins, with the corner labeled the hinge](/experiments/loss-functions/hinge-loss-shape.svg)

That corner at margin = 1 is where the loss switches from "penalty" to "no penalty." It's also why the earlier examples behave the way they do: everything to the right of the corner pays nothing, and everything to the left pays more the further left it goes.

## Softmax Loss

Another approach, called **softmax loss** (or cross-entropy loss), comes from probability theory.

Instead of just comparing two scores, it asks: "If I treat the scores as probabilities, how likely is the correct label?"

First, convert scores to probabilities using the softmax function (this is a standard trick in statistics):

```
probability_cat = exp(score_cat) / (exp(score_cat) + exp(score_dog) + exp(score_bird))
```

This converts any scores into numbers between 0 and 1 that sum to 1 (like probabilities).

Then the loss is: `loss = -log(probability_correct_label)`

If the correct label has probability 0.9, the loss is -log(0.9) ≈ 0.1 (small loss, good).

If the correct label has probability 0.1, the loss is -log(0.1) ≈ 2.3 (large loss, bad).

The logarithm means: penalize low-probability predictions harshly, reward high-probability predictions gently.

## Which Loss Function Is Right?

Hinge loss (SVM) and softmax loss are different, and they lead to slightly different learned weights. There's no universal "right" answer; it depends on your problem and your preference.

Softmax has become more popular in deep learning for a couple of reasons: it outputs a full set of probabilities (one per label, all adding up to 1), and small changes to the weights produce small, smooth changes in the loss, which makes the weights easier to adjust a little at a time. (Hinge loss has this smoothness almost everywhere too, so smoothness alone isn't the whole story; the probability output is the bigger draw.) Hinge loss is still interpretable and useful in some contexts.

The main point isn't which one you choose; it's that you *need* a loss function to:

1. Measure wrongness as a continuous number (not just right/wrong)
2. Give you a signal to optimize: "Make this number smaller"
3. Reward confident correct predictions and penalize confident wrong ones

## The Learning Loop

Here's the full loop:

1. Compute scores (Part 5)
2. Measure loss (this post)
3. Adjust weights to reduce loss (next post: gradient descent)
4. Repeat

The loss function measures how wrong the classifier is. The next post covers gradient descent, which reads that loss to work out which direction to adjust the weights, and by how much.
