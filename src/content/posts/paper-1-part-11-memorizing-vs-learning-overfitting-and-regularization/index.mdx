You build a neural network. Train it on your training set. It achieves 99% accuracy.

You try it on data it hasn't seen. 60% accuracy.

What happened? **Overfitting**.

The network memorized the training data instead of learning generalizable patterns. It latched onto quirks specific to your training set, behaving as if it had memorized rules like "if pixel 47 is exactly 128 and pixel 92 is exactly 200, it's a cat." Those exact combinations hold on the training images but fall apart on anything new.

## Training vs. Validation Accuracy

The gap between training accuracy and accuracy on a **validation set** (data held out from training to check progress, from Part 4) is the main sign of overfitting:

- **Small gap (90% train, 88% validation):** Good generalization. The network learned actual patterns.
- **Large gap (99% train, 60% validation):** Severe overfitting. The network memorized.

The bigger your network and the smaller your dataset, the more prone to overfitting it tends to be. A network with a million parameters can memorize a dataset of 1,000 images with ease.

## Regularization: Fighting Overfitting

The common thread across the techniques below is to hold the network back: make it a little harder to fit the training data exactly, so the network is nudged toward the broad pattern instead of the fine-grained quirks. Each does this in a different way.

**L2 Regularization (Weight Decay)**

Memorizing quirks takes sharp, extreme responses to tiny differences between images, and sharp responses require **large weights** (a big weight lets a single input swing the output hard). So one way to discourage memorizing is to discourage large weights. L2 regularization does exactly that, by adding a penalty to the loss that grows with the size of the weights:

```
total_loss = classification_loss + λ * (sum of squared weights)
```

Here **λ** (the Greek letter lambda) is a number you choose, the penalty strength. It makes the optimizer balance two goals: fit the training data (the first term) and keep the weights small (the second). A bigger λ pulls harder toward small weights; a smaller one lets the network fit the data more freely. The network settles on the smallest weights that still fit the data well, the gentle, general-pattern weights rather than the large, quirk-fitting ones.

Why squared, rather than just adding up the weights? Raw weights carry signs, so they would cancel out (a +1000 and a -1000 add to zero, penalizing nothing); squaring removes the sign, and because it grows fast, it comes down hardest on the few largest weights, exactly the ones that let a network overfit. Squaring isn't the only option: using the absolute value instead is a common alternative, **L1 regularization**, which tends to push weights all the way to zero rather than just shrinking them.

**Dropout**

During training, randomly "drop" (set to zero) a fraction of neurons. If 50% dropout is used, each neuron has a 50% chance of being zeroed out on each forward pass.

Why? Dropout forces the network to learn redundantly. No single neuron can carry critical information, because it might be dropped. Instead, many neurons must contribute. This discourages the network from relying on fragile, specific patterns.

At test time, every neuron stays on, and nothing special happens. Modern frameworks already compensate during training: when neurons are dropped, the ones that remain are scaled up to stand in for them, so the numbers line up once all the neurons are active at test time.

Dropout is simple and widely used.

**Early Stopping**

Monitor the validation accuracy as training goes. When it stops improving for a while, stop, even if training accuracy could still climb. (You wait rather than stopping at the first dip, since validation accuracy naturally wobbles.)

This prevents the network from overfitting over many iterations.

**More (or Augmented) Data**

The most direct cure for overfitting is simply more training data: quirks are harder to memorize across a larger, more varied set. When you can't gather more, you can augment what you have. For images, small flips, crops, and color shifts turn one example into many, all still clearly the same class.

## The Balance

Regularization reduces overfitting, but too much of it underfits: the network is so constrained it can't learn the task at all.

Getting the balance right means tuning several things:
- Penalty strength (λ)
- Dropout rate
- Network size (a bigger network needs more data to avoid overfitting)
- Amount of training

This is where hyperparameter tuning comes in: trying different settings and keeping what generalizes best. You judge "generalizes best" on the validation set; the test set stays untouched until the very end, as a final, unbiased check (Part 4), since tuning against the validation set can slowly overfit it too.
