Now we have a classifier (even if it's just nearest neighbor). How do you know if it actually works?

Answer: we test it. Run it on some images and see how many it gets right. But there's a trap here, one the CS231n notes call out as a common mistake.

## The Cheating Trap

Imagine you're studying for an exam. You have a textbook and practice problems. Here's the smart way to study:

1. Read the textbook
2. Do the practice problems (but don't memorize the answers)
3. Take a practice exam under test conditions
4. See how you did
5. Study the topics you got wrong
6. Repeat with a new practice exam

Here's the cheating way:

1. Get a copy of the exam in advance
2. Study the exact questions and answers
3. Memorize the answers
4. Take the real exam and ace it
5. Feel smart

The second person doesn't actually understand the material. They've memorized the specific test. If you change one number in a question, they're lost.

Machine learning has the exact same trap.

## The Split

The mistake looks like this: train your classifier on some images, then test it on those same images. Even the nearest neighbor classifier from Part 3 gets 100% accuracy this way, because the closest image to any training image is itself. That looks like a perfect score.

But it tells you nothing. The classifier would still fail on images it hasn't seen.

The fix CS231n recommends is to split your data into three groups:

**Training set** (typically 60-70% of your data): the images your classifier learns from. Nearest neighbor simply memorizes them. The classifiers we'll build later adjust internal settings, called weights, to fit these examples. (Separately, some settings are chosen by hand rather than learned, like how many neighbors nearest neighbor should check. These are called hyperparameters, and they get tuned on the validation set below, not the training set.)

**Validation set** (typically 15-20%): you don't train on these, but you do use them to make decisions. After building several classifiers (or one classifier with several hyperparameter settings), you check each on this set to see which does best: "Should I use this feature? How many neighbors should I check?"

**Test set** (typically 15-20%): You don't look at this until the very end, after all decisions are made. It represents "real world" images your classifier has truly never seen. Your final accuracy number comes from here, and this is what you report.

The key rule: **once you've used the test set to measure accuracy, you cannot use that score to change the classifier's design.** Peeking at the test result and then tweaking a feature or hyperparameter to improve it is cheating. You'd be using the test set to make decisions, and a test score only means something if it comes from data your classifier's design was never adjusted to fit.

## Why This Matters

This seems pedantic, but it's the difference between a classifier that actually works and one that just memorized the training data.

When you train on training data and test on training data, you're measuring something called **training accuracy**. This number is almost always better than real performance, sometimes wildly so.

When you test on held-out validation/test data, you're measuring **generalization accuracy**: how well your classifier handles images it's never seen. This is what matters in the real world.

The gap between training accuracy and test accuracy reveals **overfitting**: how much your model has memorized rather than learned. We'll talk more about this in Part 11, but the principle starts here.

## Cross-Validation

If you have a small dataset, you can't afford to hold out 20% just to measure accuracy once. In that case, machine learning uses a technique called **k-fold cross-validation**.

Imagine you have 1000 images. Instead of a single train/test split:

1. Divide the 1000 images into 5 equal groups (folds) of 200 images each
2. Train on folds 1-4, test on fold 5 → record accuracy
3. Train on folds 1-3 and 5, test on fold 4 → record accuracy
4. Repeat until every fold has been the test set once
5. Average the five accuracy numbers

This way, every image gets tested exactly once and every image is used for training four times. You get a more stable estimate of real performance without needing a huge dataset.

The metaphor: instead of one final exam, you take five quizzes on different material. Your actual grade is the average.

## The Rule You'll See Everywhere

In CS231n (Stanford's computer vision course this series works through) and every serious machine learning project, you'll see this written somewhere:

"The test set should never be used to make any decisions."

This sounds obvious until you've been staring at a low test accuracy for hours and you're tempted to "just tweak one parameter and see." Don't. Tweaking is what the validation set is for; the test set is only for the final score. If you do tune against the test set, it has effectively become another validation set, and you need a *fresh* batch of held-out images that your tweaks have never seen to serve as the real test.

The only time you look at test accuracy is at the very end, when you're reporting your final results.
