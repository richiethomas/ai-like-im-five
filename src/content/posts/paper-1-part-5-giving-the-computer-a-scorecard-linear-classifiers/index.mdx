Nearest neighbor failed because it relies on pixel-level similarity. What if we try something different: instead of comparing images directly, we compute a *score* for each possible label, then pick the label with the highest score.

This is the idea behind **linear classifiers**, called "linear" because the score is just a weighted sum of the pixel values, with no curves and no combinations between pixels.

## The Scorecard Metaphor

Imagine you're grading a student on a test. You might have a rubric like:

- Correct answer: +10 points
- Partial credit: +5 points
- Shows understanding: +3 points
- Messy handwriting: -2 points

You look at the student's work, tally up the points, and report a final score.

A linear classifier does exactly this, but for images.

Let's say we're classifying images as "cat" or "dog". We might have a rubric:

- Pointy ears present: +50 points toward "cat"
- Round face: +30 points toward "cat"
- Long snout: +40 points toward "dog"
- Floppy ears: +60 points toward "dog"

You "look at" the image (scan through its pixel values), tally up the points for each label, and pick the label with the highest score.

## How It Actually Works

In practice, a linear classifier doesn't hand-code features like "pointy ears." Instead, it assigns a weight to *every single input number* in the image.

A 32×32 color image has 1,024 pixels, and each pixel is 3 numbers (red, green, blue), so 3,072 numbers in total (this is the grid of numbers from Part 1). The classifier has one weight per number: 3,072 weights for the "cat" label and another 3,072 for the "dog" label.

The score for "cat" is computed as:

```
score_cat = w1*pixel1 + w2*pixel2 + ... + w3072*pixel3072 + bias_cat
```

Where `w1, w2, ..., w3072` are the learned weights and `bias_cat` is a constant bonus/penalty for the "cat" label.

Each weight multiplies one number in the image (say, the red value at one spot): a large positive weight means a high value there pushes the score toward "cat," a negative weight pushes it away from "cat."

(The bias is like a tiebreaker: even if the image has no distinctive features, you might favor "cat" if you've seen more cat images in training.)

The same computation happens for "dog" with different weights. Whichever score is higher wins.

## The Key Insight: Weights Are Learnable

The key difference is that these weights aren't set by hand: the computer learns them from the training data. By "learns" I mean it starts from random numbers and repeatedly adjusts them slightly based on its mistakes, improving over time.

Here's that process at a high level (Parts 6 and 7 explain each step in detail):

1. Start with random weights
2. Run the classifier on a training image
3. Compute the score for each label
4. Measure how wrong the scores were: not just whether the top score was the right label, but how far off the numbers were (Part 6 covers exactly how this is measured)
5. Adjust the weights slightly so the correct label scores a little higher next time
6. Repeat on the next training image
7. After passing through all the training images many times, the weights settle into values that make fewer mistakes on the training data (though, as we'll see, a single linear template only goes so far)

This is fundamentally different from nearest neighbor, which doesn't adjust any settings during training. Nearest neighbor stores the training images as-is and compares each new image against all of them.

## What Weights Represent

After training, you can arrange each label's 3,072 weights back into a 32×32 color image and look at them. What you see is a rough, often blurry template.

The "dog" weights tend to form a smudgy dog-like shape: areas of positive weight roughly where dogs' snouts and ears usually sit, and negative weight where they usually don't. The "cat" template looks similar but with its own arrangement, like pointier ear regions. These are not crisp pictures; they're an averaged blur of every dog (or cat) the classifier trained on.

So the classifier has learned a single template per class. The weights roughly say: "how much does this image, pixel for pixel, resemble the average dog?" and the same for cat.

But here's the limitation: because each class gets just one weighted template over the raw pixel values, a linear classifier can't hold more than one visual pattern per class. A dog can appear in many orientations, sizes, and poses. A single dog-shaped template won't match all of them. You'd need a separate template for "side view dog" and "front view dog" and "sitting dog," etc.

That single-template limit is why a linear classifier does far better on simple, consistent images than on messy real-world ones, where the same object turns up in many poses, sizes, and lighting conditions.
