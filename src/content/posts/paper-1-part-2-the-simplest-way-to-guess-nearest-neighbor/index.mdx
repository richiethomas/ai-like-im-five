In the last post, we talked about the problem: given a grid of numbers (an image), assign it a label from a fixed list (like "dog" or "cat").

Now let's try the simplest possible solution.

## The Naive Idea

Here's a strategy a child could understand: to classify a new image, find the image in your training set that looks most similar to it, and copy that image's label.

That's it. That's the entire algorithm.

If you're trying to classify a new photo of a dog, you find the training photo that's most similar to it (pixel by pixel), and you guess "dog" because that's what the training photo is labeled.

In machine learning, this is called **nearest neighbor** or **kNN** (k-nearest neighbors). It's the baseline algorithm that everyone learns first because it's trivially easy to explain.

## How Do You Measure "Similarity"?

The catch is: how do you define which images are similar?

Remember from Part 1: an image is just numbers. An 800 × 600 RGB image is 1.44 million numbers. Two images look similar to a human if they show the same thing from similar angles in similar lighting. But how do you turn that fuzzy human intuition into a mathematical definition?

The simplest approach: **compare the numbers directly**.

If image A has pixel values [100, 150, 200] and image B has pixel values [101, 151, 199], they're very close. If image C has pixel values [50, 50, 50], it's far away.

CS231n teaches two standard ways to measure this distance.

### L1 Distance (Manhattan Distance)

Add up the absolute differences between every pixel:

```
distance = |100 - 101| + |150 - 151| + |200 - 199|
         = 1 + 1 + 1
         = 3
```

This is simple and fast. For a full image, you'd add up the difference in every single pixel value across all 1.44 million numbers. It's called "L1" because mathematicians have a thing for notation.

### L2 Distance (Euclidean Distance)

Square the differences, add them up, then take the square root:

```
distance = sqrt((100 - 101)² + (150 - 151)² + (200 - 199)²)
         = sqrt(1 + 1 + 1)
         = sqrt(3)
         ≈ 1.73
```

This is the distance you learned in high school geometry — the straight-line distance between two points. It punishes large differences more than small ones (because of the squaring).

On the CIFAR-10 dataset (a standard benchmark of 60,000 small images), L1 achieved about 38% accuracy and L2 achieved about 35% on a test set. That's barely better than random guessing (which would be 10% on 10 categories).

## Why This Fails

Nearest neighbor seems intuitive until you actually try it on real images. Then it falls apart.

The problem is **pixel-level similarity is not semantic similarity**. Two images can have very different numbers but show the same thing. Two images can have very similar numbers but show completely different things.

A dog photographed in shadow might have numbers [20, 25, 30] for a particular pixel. The same dog in bright sunlight might have [200, 210, 220] for that pixel. These numbers are nothing alike, even though it's the same dog.

Meanwhile, a dog and a wolf have very similar shapes and textures. They might have nearly identical pixel values in many places. But one is a dog and one is a wolf.

Nearest neighbor doesn't care about what the pixels *mean* — just how close the numbers are. It matches based on accident visual similarity (lighting, angle, background) rather than actual content.

This is why, as you add more challenging variations — viewpoint changes, scale changes, occlusion — nearest neighbor gets worse and worse. It's trying to solve the problem with pixel arithmetic when the problem is fundamentally about *semantic content*.

## The Insight

But here's what nearest neighbor teaches us: **we can't solve image classification with pixel-level comparisons alone**. We need to extract something deeper from the images — features or patterns that are more robust to the seven challenges we listed in Part 1.

This is where the rest of CS231n comes in. Every technique we'll learn — linear classifiers, neural networks, convolutional networks — is building on this insight: find a better representation of the image than raw pixels, then classify based on that representation.

Nearest neighbor fails because it uses raw pixels. Everything that comes next is about avoiding that trap.
